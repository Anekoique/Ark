# `ark-workflow-refactor` PRD

---

[**What**]

Refactor the Ark task lifecycle to replace the per-task `/ark:archive` slash command with an atomic `/ark:commit` closure step (commit + journal + SPEC extract), make `ark archive` a manager-only bulk CLI, capture `start_head` at task creation so the journal entry can record the start of the task's commit range (the closing commit itself cannot embed its own SHA inline — see Outcome item 7), and reshape `VERIFY.md` into a living checklist + findings document seeded from project/feature SPEC indices and the PRD.

[**Why**]

Two compounding problems with the current workflow drove this refactor:

1. **Archive happens too early.** Today, `/ark:archive` closes a task immediately after VERIFY. PR-review feedback that arrives later forces awkward "revise after archive" detours, and the workspace journal's commit-collection logic falls back to `git log -n 20` because the task's start commit was never captured. The current `fix-record-task-commit-range` band-aid does not solve the root issue.
2. **VERIFY is a verdict ceremony, not a working artifact.** The single-pass Approved/Rejected verdict masks the need for compliance auditing against the project's own SPECs. The `codex-support` task surfaced this: VERIFY approved with minor follow-ups, but a separate cleanup pass found ~5 sites of structural redundancy that should have been findings.

A third concern — the boundary between REVIEW and VERIFY — is **deliberately preserved** rather than collapsed. REVIEW evaluates the *plan* pre-execute; VERIFY audits the *implementation* post-execute. They share scaffolding (verdicts, findings, severity) but answer different questions. Folding them together loses the distinction; the right move is to strengthen VERIFY's duties without merging the two stages.

[**Outcome**]

A user running `/ark:design --deep <title>` on a fresh install observes the new lifecycle end-to-end:

1. **Lifecycle is** `design → plan ⇄ review → execute → verify → commit → (bulk-archived later)`.
   Quick: `design → execute → commit`. Standard: `design → plan → execute → verify → commit`. Deep: `design → plan ⇄ review → execute → verify → commit`.
2. **`/ark:commit [-m "<msg>"] [--no-commit]`** is the new closure slash command. Default behavior: agent generates a conventional-commits message from the staged diff + recent `git log` style, shows it for confirmation/edit, then runs an atomic sequence — phase transition to `committed`, deep-tier SPEC extraction to `specs/features/<slug>/SPEC.md`, single git commit covering work + journal entry + task.toml + (deep) SPEC + features INDEX, journal write to `.ark/workspace/<dev>/journal-N.md` with `**Start Head**` and `**Base Branch**` fields (no inline closing SHA — see Outcome item 7 for the recovery primitive). `-m "<msg>"` skips message generation. `--no-commit` skips both git commit and journal write; only deep-tier SPEC extraction runs (user takes responsibility for their own commit + record).
3. **`/ark:commit` requires uncommitted changes** (workflow agreement: every task ends with a committing action). Clean working tree → hard error: "task commit requires staged work; this is the final task commit." No fallback to a separate journal-only commit.
4. **VERIFY.md is a living checklist + findings document** filled by the implementer during EXECUTE → COMMIT. No verdict, no loop. Six sections: four auto-seeded checklist sections (Project Spec Compliance from `.ark/specs/project/INDEX.md`, Related Feature Spec Compliance from PRD's `[**Related Specs**]`, PRD Constraints from PRD's Outcome and Constraints, Plan Fidelity), one fixed checklist section (SPEC Drift), and one open-ended Findings section (V-NNN entries with Severity, Location, Problem, Recommendation, Resolution). Plus Notes. Items resolve to `PASS` / `FAIL: <reason>` / `N/A: <reason>`; findings resolve to `FIXED in <commit>` / `ACCEPTED — <reason>`. Document is complete when no item or finding is `PENDING`. **Tier-conditional gate at `/ark:commit`:** deep refuses if any item or finding is `PENDING`; standard warns and proceeds; quick has no VERIFY.
5. **`/ark:archive` and the `ark agent task archive` slash-driven path are removed.** A new top-level `ark archive` CLI is the manager-only bulk closure: scans `.ark/tasks/*/task.toml` for `phase = committed`, moves each to `.ark/tasks/archive/YYYY-MM/<slug>/` (month chosen from each task's commit timestamp), and is idempotent. `--dry-run` reports without moving. The `/ark:archive` slash command, the codex `ark-archive` skill, and the OpenCode `archive.md` are all deleted. The underlying `ark agent task archive` function is preserved as a manager helper called internally by `ark archive` — only its user-facing slash-command surface is removed.
6. **Phase enum gains `Committed`.** New legal transitions: `Verify → Committed` (standard/deep), `Execute → Committed` (quick), `Committed → Archived` (manager bulk, internal). The `Archived` phase persists in `task.toml` after bulk archive. Existing `Verify → Archived` and `Execute → Archived` direct transitions are removed; bulk archive only operates on `Committed` tasks.
7. **Recoverable journal commit range, anchored to the slug.** `task new` captures `start_head = git rev-parse HEAD` at creation time, stored in `task.toml.start_head`. `/ark:commit` writes the journal entry with `**Start Head**: <start_head>` and `**Base Branch**: <base_branch>` fields. The closing commit's SHA is **not** rendered into the journal entry body (that would be self-referential — Git's content-addressed object model makes it physically impossible to embed a commit's own SHA inside that commit). The complete range `<start_head>..<closing-commit-sha>` is recoverable any time later via a slug-anchored search of the journal file's git history: `git log -S '**Slug**: <slug>' --format=%H -n 1 -- <journal-path>`. `-S` (pickaxe) matches commits whose diff changed the *count* of the literal string `**Slug**: <slug>` — the closing commit's diff added the field (count went from 0 to 1, so `-S` matches), and amend/revert sequences that re-add and re-delete the same string produce a net-zero count change (so they do not match). The slug field is unique per journal by construction (each task is recorded exactly once). The recovery primitive remains valid after later manual `/ark:record` entries (manual entries omit the `**Slug**` field's task-slug content — they render `**Slug**: -`, which never collides with a real task slug) and after later task commits append to the same `journal-N.md` file before rotation (each task adds its own slug, and `-S` for one slug ignores the others). The closing commit is intentionally absent from the entry's commits-in-range table because the table is rendered before the closing commit exists; readers wanting the closing commit run the `-S` search. (This is the PRD's authoritative wording; the original draft asked for the SHA inline in the journal entry, but that was physically impossible — see iteration 01's REVIEW R-001 and iteration 02's REVIEW R-104 for the chain that brought us here, and iteration 02's REVIEW R-201 for why a path-only `git log -n 1 -- <journal-path>` lookup is unreliable. An earlier draft of this iteration included `--diff-filter=A` in the recovery command; that was withdrawn during execution because git's `--diff-filter=A` matches whole-file additions only, not line additions, and the journal file pre-exists the closing commit.)
8. **Migration on `ark upgrade`:** existing in-flight tasks in `phase = "verify"` keep their phase; their `VERIFY.md` is regenerated with the new checklist sections (preserving any existing Findings prose). Existing `phase = "archived"` tasks are untouched. Tasks created before this refactor lack `start_head`; their `/ark:commit` runs degrade gracefully to a `git log -n 20` fallback for journal commit collection (one-time, only for pre-refactor tasks).
9. **Workflow doc, AGENTS.md, and slash-command/skill templates updated** to reflect the new lifecycle, the new `/ark:commit`, and the removal of `/ark:archive`. Across all three platforms (Claude / Codex / OpenCode), the refactor lands in lockstep — no platform may diverge.

User-defined workflow chains (a `[workflow]` section in `.ark/config.toml`) are explicitly **out of scope** for this task and deferred to a follow-up; the PRD only sketches the shape so the refactor doesn't paint into a corner. Bulk archive triggered by version-bump is similarly out of scope — `ark archive` is invoked manually.

[**Related Specs**]

- `.ark/specs/features/workspace/SPEC.md` — workspace journal storage and shape; this task replaces the `git log -n 20` fallback in `record_task` with a `git log <start_head>..HEAD --oneline -n 20` range for task-driven entries (when `start_head` is present in `task.toml`). Manual `/ark:record` path is unaffected. Adds two new rendered fields to per-task journal entries: `**Start Head**: \`<start_head>\`` and `**Base Branch**: \`<base_branch>\`` between the existing `**Branch**` field and the `### Summary` heading. **No inline closing-SHA field is rendered** (see Outcome item 7 for why); the closing commit's SHA is recoverable via the slug-anchored `git log -S` primitive described in Outcome item 7. Manual `/ark:record` entries omit both new fields entirely.
- `.ark/specs/features/task-concurrency-control/SPEC.md` — `.ark/.state.toml` and the `Phase` enum; this task adds the `Committed` variant, retires the `Verify → Archived` and `Execute → Archived` transitions, and adds the `Verify → Committed` / `Execute → Committed` / `Committed → Archived` transitions. The state-file reconcile loop's add-pass and drop-pass behavior is unchanged in shape but must learn to keep `Committed` tasks in `tasks.active` (a committed task is not yet archived) and drop them only when bulk-archived.
- `.ark/specs/features/ark-agent-namespace/SPEC.md` — `ark agent` verb set; this task adds the new internal verb `ark agent task commit` (the structural mutation invoked by `/ark:commit`) and removes user-facing `ark agent task archive` invocation from slash commands (the underlying function is preserved as a manager helper called by the new top-level `ark archive` CLI). The hidden, non-semver-stable nature of `ark agent` is preserved.
- `.ark/specs/features/ark-context/SPEC.md` — `ark context --for <phase>` projections; this task replaces the `verify` projection's downstream consumer (the slash command no longer reads VERIFY's verdict line; it inspects checklist/findings completeness instead) and adds a `commit` projection scope.
- `.ark/specs/features/ark-upgrade/SPEC.md` — template re-render and migration policy; this task adds a one-shot migration step to regenerate in-flight `VERIFY.md` files and to rewrite installed slash-command templates that reference `/ark:archive` or the verdict-driven VERIFY shape. Existing non-destructive patching policy is preserved.
- `.ark/specs/features/worktree/SPEC.md` — worktree mechanics; this task does not change worktree creation or cleanup, but the worktree's `.ark/` is now the cwd from which `/ark:commit` runs (exact range and SPEC extract operate on the worktree's tree), matching the existing rule for `/ark:plan`, `/ark:review`, etc.
- `.ark/specs/features/codex-support/SPEC.md` and `.ark/specs/features/opencode-support/SPEC.md` — platform-parity SPECs; this task adds `/ark:commit` and removes `/ark:archive` across all three platforms (Claude commands, Codex skills, OpenCode commands) in lockstep.
- `.ark/specs/features/project-spec/SPEC.md` — project-spec layout (`Layout A`); this task does not modify the SPEC layout itself but does consume `.ark/specs/project/INDEX.md` at VERIFY-seed time to enumerate Project Spec Compliance items in the new VERIFY checklist.
