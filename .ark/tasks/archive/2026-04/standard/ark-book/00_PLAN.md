## Spec

[**Goals**]

- **G-1:** Zero task-mark tags remain in `crates/` source comments after the sweep. The sweep targets these tag families inside `///`, `//!`, and `//` comments only:
  - Validation tags: `V-IT-N`, `V-UT-N`, `V-E-N`, `V-F-N`
  - Plan-spec tags: `G-N`, `NG-N`, `C-N`, `T-N`, `TR-N`, `M-N`
  - Review/follow-up tags: `R-N`, `FU-N`
  - Optionally feature-scoped: `<feature-name> <tag>`, e.g. `worktree-support C-7`, `ark-context C-18`, `codex-support G-12`.
- **G-2:** Stripped comments stay grammatical and information-preserving. The *prose* explaining a constraint stays; only the tag tokens (and the surrounding scaffolding — `Per X:`, `(per X)`, `<feature> <tag>:`, parenthetical traceability lists) come out. Lines that become empty after the strip are deleted.
- **G-3:** Source-scan invariant comments survive in spirit. Several test fixtures lock the strip itself in: any `// codex-support C-18: source-scan invariant for X.rs.` style fixture is rewritten to assert *the absence of the tag pattern*, not the absence of the literal string `C-18` (otherwise the strip itself fails the test).
- **G-4:** `docs/book/` is a working mdBook project: `book.toml` + `src/SUMMARY.md` + chapter files. `mdbook build docs/book` succeeds with no broken links, no missing `SUMMARY` entries.
- **G-5:** Book content covers five parts: Getting Started, Workflow, CLI Reference, Platform Integrations, Contributing. Each part is sourced from existing canonical material (`README.md`, `AGENTS.md`, `.ark/workflow.md`, the seven feature SPECs in `.ark/specs/features/`); the book is reorganization, not net-new prose, except for the Contributing chapters which port material from `AGENTS.md`.
- **G-6:** A GitHub Actions workflow at `.github/workflows/book.yml` builds the book and deploys to GitHub Pages. Triggers: `push` of tags matching `v*` (matches `dist`'s release trigger) and `workflow_dispatch`. Uses the `actions/deploy-pages@v4` flow with `actions/configure-pages` + `actions/upload-pages-artifact`.
- **G-7:** `cargo build --workspace`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check` all pass after the cleanup. No doc-test breaks from the strip.

[**Non-goals**]

- **NG-1:** No version bump in `Cargo.toml`. The user handles that separately, post-merge.
- **NG-2:** No strip of tags in `templates/`, `.ark/templates/`, `.ark/specs/`, `.ark/tasks/archive/`, `docs/` (excluding the new `docs/book/`), or any markdown. Tags inside SPECs and PLANs are intentional cross-references.
- **NG-3:** No versioned book hosting (one published version per release, latest wins).
- **NG-4:** No rustdoc landing page on GH Pages. `cargo doc` is enough; the book is for users, not API browsing.
- **NG-5:** No i18n; English only for v1.
- **NG-6:** No custom theme / styling beyond mdBook defaults (toc, search, copy-button).
- **NG-7:** No deploy on `main` push — only on tag and manual dispatch.
- **NG-8:** No CHANGELOG file. Release notes live on GitHub Releases (auto-generated by `dist`).

[**Constraints**]

- **C-1:** Comment strip is regex-driven but **not blind sed**. Every match is reviewed file-by-file via the `Edit` tool because comment phrasing varies (some lines need full deletion, some need rewording when the tag was the subject of the sentence, some have multiple tags on one line). No `sed -i` across the tree.
- **C-2:** The strip is restricted to `crates/`. Tags inside `templates/`, `.ark/templates/`, `.ark/specs/`, `.ark/tasks/archive/`, and `docs/` (other than the new `docs/book/`) are intentional cross-references and stay.
- **C-3:** False-positive guard: `T-N` and `M-N` patterns collide with valid Rust syntax (generic params, macro names). The strip's regex matches inside comment lines only, but the executor still eyeballs every `T-` and `M-` hit before editing.
- **C-4:** Source-scan invariant tests (`codex-support C-18`-style fixtures in `platforms.rs`, `remove.rs`, `unload.rs`, `load.rs`) currently assert that *certain rules from those tasks remain enforced in source*. The strip rewrites these tests to keep their *behavioral* assertion (e.g. "no bare `std::fs::*` in this module") and drop the *tag-name* part of the message.
- **C-5:** The book's edit-url-template assumes `main`-branch hosting of `docs/book/src/`. If the repo's default branch ever becomes `dev` or similar, this string needs updating; out-of-scope for this task.
- **C-6:** `actions/deploy-pages@v4` requires `pages: write` and `id-token: write` permissions on the workflow job. The workflow declares these explicitly; no org-level setting is changed by this PR (Pages must be enabled in repo settings as a one-time manual step — call this out in the PR description).
- **C-7:** `book.toml`'s `git-repository-url` and `edit-url-template` use the canonical `https://github.com/Anekoique/ark` URL (matches `[workspace.package].repository`). One source of truth.
- **C-8:** mdBook version is pinned in the workflow (`mdbook --version` printed in the build step). Floating versions break reproducibility.

## Runtime

[**Main Flow**]

1. **Phase 1 — comment strip.** For each of the 38 affected files, run an `Edit` per comment block: remove tag tokens, prune empty lines, rewrite test invariant messages. Commit per logical group (e.g. one commit per directory: `commands/`, `commands/agent/`, `commands/context/`, `io/`, top-level).
2. **Phase 2 — book authoring.** Create `docs/book/` skeleton (`book.toml`, `SUMMARY.md`, empty chapter files). Then fill chapters by porting from `README.md`, `AGENTS.md`, `.ark/workflow.md`, and the seven feature SPECs. Commit per part (5 commits: getting-started, workflow, reference, platforms, contributing).
3. **Phase 3 — CI deploy.** Author `.github/workflows/book.yml`. Smoke-test via `workflow_dispatch` from a draft branch is *not* possible until the workflow is on `main`, so verification is local: `mdbook build docs/book` succeeds + a manual checklist for the workflow's YAML correctness.
4. **VERIFY gate.** Run `cargo build/test/clippy/fmt`, run `mdbook build docs/book`, run the grep guard from PRD's Outcome to confirm zero tag hits remain.

[**Failure Flow**]

1. **Strip breaks a doc-test.** A doc-test in a `///` comment depended on the tag scaffolding (very unlikely — tags appear in prose, not code blocks). Restore the doc-test, re-strip more carefully.
2. **Strip breaks a unit test.** A test that asserts a literal tag string in source (the source-scan invariant tests). Rewrite the test per C-4 to assert the *pattern* not the *literal*.
3. **Strip changes meaning.** Reviewer flags that a stripped comment now reads ambiguously. Restore the relevant prose; tag tokens stay out.
4. **`mdbook build` warns/errors on broken link.** Fix the link or delete the chapter reference; re-build.
5. **GH Pages workflow fails on first tag push.** Pages not enabled in repo settings, or branch protection blocks the deploy. PR description calls out the one-time enablement; otherwise iterate post-merge.

[**State Transitions**]

- *Source has tags* → *Source is tag-free* — after Phase 1 commits land.
- *No `docs/book/`* → *`docs/book/` builds locally* — after Phase 2 commits land.
- *No deploy* → *Deploy on tag* — after Phase 3 commit lands and Pages is enabled.

## Trade-offs

- **T-1: Comment strip granularity.** Option A — keep prose, drop tags only (chosen). Option B — rewrite every comment from scratch against the global "default to no comments" rule. Option B is a much bigger semantic change with real risk of dropping load-bearing context; A is a targeted lint that gets us version-bump-clean. If a future task wants to do B, it can.
- **T-2: Cleanup commit cadence.** Option A — one giant "comment cleanup" commit (atomic, easy to revert). Option B — one commit per directory grouping (chosen). B keeps each commit reviewable in isolation; the revert blast radius is one directory, which is fine.
- **T-3: Book engine.** mdBook (chosen) vs Docusaurus / VitePress. mdBook is the Rust-ecosystem default, builds in seconds, single binary, zero JS runtime, search built in. Docusaurus and VitePress are more flexible but bring a Node toolchain we don't otherwise need.
- **T-4: Deploy trigger.** Option A — deploy on tag push (chosen, matches `dist`). Option B — deploy on every push to `main`. A means the published book reflects what users have installed; B is simpler but creates skew (book may document features not yet in the released CLI).
- **T-5: Source-scan invariant tests.** Option A — keep the test, rewrite the message to drop the tag (chosen). Option B — delete the test outright since its origin tag is gone. A keeps the *invariant* (e.g. "no bare `std::fs::*` in this module"), which is the test's actual value; B throws out the baby.
- **T-6: Versioned book hosting.** Option A — one published version per release, latest wins (chosen). Option B — `https://anekoique.github.io/ark/v0.2.0/` with a version switcher. B is real work; A is one workflow file. B can come later if there's demand.

## Validation

[**Unit Tests**]

- **V-UT-1:** Source-scan tests in `platforms.rs`, `remove.rs`, `unload.rs`, `load.rs` continue to pass after the rewrite. The behavioral assertion (e.g. "no bare `std::fs::*`") survives; only the tag-name reference in the docstring or message is removed.
- **V-UT-2:** `cargo test --workspace` passes with zero failures, zero ignored-by-tag, zero new `#[should_panic]`s.

[**Integration Tests**]

- **V-IT-1:** Existing `commands/init.rs::tests` and `commands/load.rs::tests` round-trip suites pass unchanged. The strip touches only doc-comments, not template files or runtime code, so behavioral tests are unaffected.
- **V-IT-2:** `mdbook build docs/book` produces `docs/book/book/` with exit 0 and no `WARN` / `ERROR` lines on stderr.
- **V-IT-3:** Every `[link](path)` inside the rendered book resolves. `mdbook test` is a no-op for non-Rust books; the link check is the manual sweep against the build output's HTML.

[**Failure / Robustness Validation**]

- **V-F-1:** If the strip leaves a doc-comment grammatically broken (e.g. `/// : every Claude slash command…` because the tag was the subject), the executor catches it during file-level review and rewrites the prose.
- **V-F-2:** `mdbook build` on a missing chapter file (referenced in `SUMMARY.md` but not present) errors with a clear message — caught locally before commit.
- **V-F-3:** The Pages workflow on first tag push: if Pages is not enabled in repo settings, the `actions/configure-pages` step fails with a clear error and the user enables Pages, then re-runs via `workflow_dispatch`.

[**Edge Case Validation**]

- **V-E-1:** Tags that appear inside *string literals* in tests (e.g. `assert!(s.contains("V-UT-1"))`) — these are not comments and stay. Caught by restricting the strip to lines starting with `///`, `//!`, or `//` (after stripping leading whitespace).
- **V-E-2:** A doc-comment whose entire content is a tag (e.g. `/// C-17.`) — the line is deleted, not left as `/// `.
- **V-E-3:** A `Per <feature> <tag>` clause inline mid-sentence — strip the clause, fix the surrounding punctuation. Reviewed per-edit, not regex-replaced.
