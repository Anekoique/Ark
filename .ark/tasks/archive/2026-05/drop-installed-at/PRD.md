# `drop-installed-at` PRD

---

[**What**]

Remove the `installed_at` timestamp field from `Manifest` (`.ark/.installed.json`).

[**Why**]

The timestamp churns on every `ark upgrade` even when no other change occurs, producing a spurious manifest diff with no observable benefit. The field has no functional consumers — only `init` writes it (via `Manifest::new`) and `upgrade` refreshes it; nothing reads it. Dropping it eliminates the redundant write and the noisy diff.

[**Outcome**]

- `Manifest` struct no longer has an `installed_at` field; `chrono::{DateTime, Utc}` import is removed from `crates/ark-core/src/state/manifest.rs`.
- `crates/ark-core/src/commands/upgrade/mod.rs` no longer assigns `manifest.installed_at`; `chrono::Utc` import is removed from that file.
- The legacy-deserialization test (`legacy_manifest_without_hashes_field_deserializes`) still passes — `serde` ignores the unknown `installed_at` field on read.
- `.ark/.installed.json` regenerated by `ark init` / `ark upgrade` contains no `installed_at` key.
- `cargo build -p ark-core` and `cargo test -p ark-core` succeed with no new warnings.
- `.ark/specs/features/ark-upgrade/SPEC.md` is updated to drop the two `installed_at` references (data-structure block and upgrade pipeline diagram).

[**Related Specs**]

- `specs/features/ark-upgrade/SPEC.md` — declares the `Manifest` data structure and the upgrade pipeline that refreshes `installed_at`; both references need removal.
